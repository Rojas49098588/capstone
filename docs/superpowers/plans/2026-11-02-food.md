# Food Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Berry Bites lifts a struggling pet's shown mood one step for 2 hours, and Power Bento boosts the project's tokens ×1.1 for 4 hours. Both have feeding limits, an explanation in the Shop, and a Food section in the habitat with countdowns.

**Architecture:** A new pure module, `web/src/planner/food.ts`, works out every effect, limit and countdown from a new `fed` event plus the current time. Nothing new is stored except that event. The snack lift is applied on top of the existing mood in `petMood` and `summarizeProject`, so the habitat, the project list and the desktop overlay (`store/petStatus.ts`, which calls `petMood`) all show it. `projectHealth` and the neglect logic never see it. The meal boost is one more multiplier in `computeCompletionPayout`, next to `sickMultiplier`.

**Tech Stack:** TypeScript, React, Vitest with Testing Library, all in `web/`.

**Spec:** `docs/superpowers/specs/2026-11-02-food-design.md`

## Global Constraints

- Snack: Berry Bites, product id `berry-bites`. Shown mood +1 step (Upset → Worried, Worried → Happy, everything else unchanged) for 2 hours. One every 2 hours, per pet.
- Meal: Power Bento, product id `power-bento`. Tokens on the pet's project × 1.1 for 4 hours. One per local day, per pet (resets at local midnight; use `localDateKey`). If a boost is already running, a meal moves its end 4 hours later and never raises the multiplier.
- Never feed eggs, Sick pets or Recovering pets. Food never changes `projectHealth`, neglect, the gap or the idle clock.
- Snack is refused with "Not hungry" unless the pet's mood is Worried or Upset.
- Numbers go in `web/src/planner/tuning.ts`: `SNACK_PRODUCT_ID`, `MEAL_PRODUCT_ID`, `SNACK_HOURS = 2`, `MEAL_HOURS = 4`, `MEAL_TOKEN_MULTIPLIER = 1.1`.
- Shop copy, exact text:
  - Berry Bites: "Lifts a Worried or Upset pet's mood one step for 2 hours. One snack every 2 hours. Doesn't help a Sick pet."
  - Power Bento: "Tasks on this pet's project earn × 1.1 tokens for 4 hours. One meal a day."
- Habitat copy, exact text:
  - "Snack: lifting mood for {d} more"
  - "Meal: × 1.1 tokens for {d} more"
  - "Next snack in {d}"
  - "Next meal tomorrow"
  - "Boost already on: this adds 4 hours instead of doubling it."
  - "Not hungry"
  - Mood suffix "({from}, lifted by a snack)"
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feature/food`, cut from `main`, never on `main`.
- Web tests run from `web/` with `npx vitest run <path>`. Full web suite: `npx vitest run`, plus `npx tsc -b` (or the repo's `npm run build`) for types.

## Review Focus

1. **Edges of the time windows.** At exactly 2h after a snack the lift is over and a new snack is allowed. At exactly 4h after a meal the boost is over. Pinned in Task 1.
2. **Meals either side of midnight.** A meal at 11:30 PM and another at 12:10 AM by the same pet are both allowed, and the second extends the boost to 4:00 AM + 4h. Pinned in Task 1.
3. **Old saved data and bad saves.**
   - Completions saved before this change have no `foodMultiplier` and must still load and count.
   - A `fed` event with a bad shape is rejected, the same as other events.
   - Pinned in Task 1 (storage) and Task 3.
4. **A pet that got sick while a boost runs.** The payout gets both multipliers (0.5 × 1.1). Pinned in Task 3.
5. **The schedule moves during a lift.** A fed pet whose schedule mood rises to Happy shows Happy, not Delighted. One that drops to Upset shows Worried. Pinned in Task 2.

Also: a `fed` event stamped after `now` (the computer clock was moved) is ignored. Pinned in Task 1.

- Consumes:
  - `ProjectMood` from `mood.ts`. Task 2 adds `liftedFrom` to it. In this task `withSnack` sets `liftedFrom`, so add the field to the `ProjectMood` type here, with `projectMood` returning `liftedFrom: null`.
